## Executive Summary

v0.4.0 was already public and had real release hygiene problems: stale `uv.lock`, open v0.4.0 milestone issues, stale docs, and a live overlay verifier/cleanup path that was too fragile for a trust release.

The v0.4.1 recovery branch fixes the important stuff:

- package version and `uv.lock` now agree on `0.4.1`;
- update diagnostics now report inherited `VIRTUAL_ENV` mismatches truthfully;
- WSL/Windows overlay launch no longer runs Electron directly from WSL UNC renderer paths, it mirrors the overlay app into the Windows Electron cache first;
- overlay shutdown now uses bounded retry and broader cleanup of Hermes Pets Electron cache processes;
- the live overlay verifier has bounded retry for Windows/Electron startup and teardown races;
- release-facing docs and release notes were refreshed;
- GitHub issues #65-68 were closed with completion comments.

The validation stack is green locally. The remaining minor release risk is operational, not code-level: this branch still needs approval, push/merge, and CI visibility before a public `v0.4.1` tag/release.

## Confirmed v0.4.1 Scope

v0.4.1 is a corrective patch release for v0.4.0. It appears to include:

- Version/lockfile recovery:
  - `pyproject.toml` bumped to `0.4.1`.
  - `uv.lock` regenerated to `hermes-pet 0.4.1`.
- Update command trust fix:
  - `_python_environment_hint()` now prefers the invoked executable's environment and explicitly reports inherited `VIRTUAL_ENV` mismatches.
  - Regression coverage for mismatched `VIRTUAL_ENV`, matching venv, uv tool environment, and standalone executable with inherited env.
- WSL/Windows overlay reliability fix:
  - PowerShell launcher mirrors the overlay app to `%LOCALAPPDATA%\HermesAgent\pet-overlay-electron\app-<port>` before launching Electron.
  - Launcher detects/stops stale Electron processes from the Hermes Pets Electron cache, not just the root process with `main.windows.js` in the command line.
  - Launcher stop path uses bounded retry instead of a single 500ms wait.
  - Renderer readiness has startup fallback and a load watchdog event.
- Live verifier recovery:
  - `scripts/verify-live-overlay.sh` uses isolated Electron user-data for verifier runs.
  - The verifier retries up to three attempts before failing, because Windows/Electron startup and teardown can transiently race.
- Docs and issue hygiene:
  - `CHANGELOG_LOCAL.md`, `README.md`, and `CURRENT_STATE.md` updated.
  - `release-readiness/v0.4.1-recovery.md` and `release-readiness/v0.4.1-release-notes-draft.md` created.
  - GitHub issues #65, #66, #67, and #68 closed as completed.

Explicitly not included:

- No PyPI publication.
- No Windows installer.
- No hosted dashboard.
- No hosted custom-pet gallery.
- No native Linux/macOS/native Windows full-overlay support expansion.
